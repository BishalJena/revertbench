    How it works
    
          
    A passing test alone can miss a bug. The same test has to distinguish the broken code from the repaired code.
    
        
    
        
      
          
    1. 
            
      Start with a real bug
      
            
      Find a change that broke existing behavior and the later fix. Keep the code before the change, the buggy code, and the buggy code with the fix applied.
      
          
      2. 
          
    2. 
            
      Give the AI a reviewer’s job
      
            
      Show the model the proposed change and ask it to write a test. Keep the later fix and the maintainers’ test hidden from the model.
      
          
      3. 
          
    3. 
            
      Check what the test proves
      
            
      Run the submission in isolated Docker containers. It must fail on the buggy code for the expected reason, pass with the repair, and repeat those outcomes consistently.
      
          
      4. 
        
    
        
    
          What the replay measures
          
    The site replays the maintainers’ reference tests. They show that each historical bug can be detected. Comparative model results are pending.
